Базовый URL: `http://localhost:<PORT>` (где `<PORT>` — порт, указанный в `.env`, по умолчанию `3000`)

### GET `/api/getpairs`

**Описание:** Получить список занятий на указанный день для группы, преподавателя или аудитории.

**Query-параметры:**

| Параметр | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `type` | `string` (`group` \| `teacher` \| `auditory`) | ✓ | Тип поиска: по группе, преподавателю или аудитории. |
| `data` | `string` | ✓ | Значение для поиска (название группы, ФИО преподавателя или номер аудитории). Используйте `group` для обратной совместимости, но `data` является предпочтительным. |
| `date` | `string` | ✓ | Дата в формате `DD.MM.YYYY` или `YYYY-MM-DD`. |

**Ответ (HTTP 200 OK):** Массив объектов занятий. Если для целевой даты в таблиц�� `pairs` не заполнено поле `date` (например, расписание загружено понедельно), эндпоинт выполняет fallback-поиск по `weekday` и диапазону `date_start`/`date_end`, чтобы данные корректно выдавались и в режиме отображения «На день».

```json
[
  {
    "id": 42,           // `number` Уникальный идентификатор занятия
    "type_lesson": "Лекция", // `string` Тип занятия
    "subject": "Математика", // `string` Название дисциплины
    "teacher": "Иванов И.И.", // `string` ФИО преподавателя
    "auditory": "101",      // `string` Номер аудитории
    "time": 1,             // `number` Номер пары
    "time_start": "08:00",   // `string` Время начала пары (ЧЧ:ММ)
    "time_end": "09:30",     // `string` Время окончания пары (ЧЧ:ММ)
    "group": ["ИТ-21"]      // `array<string>` Список групп, для которых проводится занятие
  }
]
```

**Legacy-формат:** `GET /api/getpairs/{type}:{group}:{date}`. Этот формат устарел и не рекомендуется к использованию. Используйте Query-параметры.

**Описание:** Получить список всех групп, доступных в системе. Список формируется из данных расписания (`pairs`) и ручного каталога групп (`group_catalog`).

**Query-параметры:**

| Параметр | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `course` | `number` | Нет | Номер курса для фильтрации групп. Если не указан, возвращаются группы со всех курсов. |

**Ответ (HTTP 200 OK):** Массив строк, содержащих названия групп.

```json
["ИТ-21", "ИТ-22", "ПИ-21", ...]
```

**Legacy-формат:** `GET /api/getgroups/{course}`. Этот формат устарел и не рекомендуется к использованию. Используйте Query-параметры.

### POST `/api/unified-window/tickets`

**Описание:** Создать новое обращение в модуле «Единое окно». Этот эндпоинт доступен без авторизации.

**Тело запроса (Request Body):** `application/json`

| Поле | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `role` | `string` (`visitor` \| `student` \| `teacher`) | ✓ | Роль заявителя. Для обратной совместимости также поддерживается поле `requester_role` с теми же значениями. Если переданы оба, п��иоритет у `requester_role`. |
| `contact_name` | `string` | ✓ | Имя заявителя. |
| `contact_email` | `string` | ✓ | Email заявителя. **Обязателен**, так как используется для последующего поиска обращений. |
| `subject` | `string` | ✓ | Тема обращения. |
| `message` | `string` | ✓ | Текст первого сообщения в обращении. |

```json
// Пример запроса
{
  "role": "student",
  "contact_name": "Иван Иванов",
  "contact_email": "ivan@example.com",
  "subject": "Проблема с расписанием",
  "message": "Не открывается расписание группы ИТ-21"
}
```

**Ответ (HTTP 200 OK):** Объект, содержащий статус операции, ID созданного обращения и токен доступа.

```json
// Пример успешного ответа
{
  "ok": true,          // `boolean` Статус операции
  "id": 12,            // `number` ID созданного обращения
  "access_token": "a1b2c3d4..." // `string` Уникальный токен для доступа к обращению
}
```

**Обр��ботка ошибок:** При внутренних ошибках создания обращения диагностические детали записываются в серверный лог (`logs/server.log`).

**Хранение данных:** Данные обращения хранятся в БД `users.sqlite` в таблицах `unified_window_tickets` и `unified_window_messages`. Сообщения и чувствительные поля обращения (тема, имя, email) шифруются с использованием `AES-256-GCM` для обеспечения конфиденциальности.

### POST `/api/unified-window/tickets/{token}/reply`

**Описание:** Добавить новое сообщение от пользователя в существующее обращение. Доступно только для активных обращений.

**Параметры пути (Path Parameters):**

| Параметр | Тип | Описание |
| --- | --- | --- |
| `token` | `string` | Уникальный токен доступа к обращению. |

**Тело запроса (Request Body):** `application/json`

| Поле | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `message` | `string` | ✓ | Текст сообщения от пользователя. |
| `contact_name` | `string` | ✓ | Имя пользователя, отправляющего сообщение. |

**Ограничение:** Если статус обращения `closed` или `resolved`, отправка сообщений запрещена. Сервер вернёт HTTP 400.

```json
// Пример запроса
{
  "message": "Есть обновление по проблеме",
  "contact_name": "Иван Иванов"
}
```

**Ответ (HTTP 200 OK):** Объект, содержащий статус операции и ID созданного сообщения.

```json
// Пример успешного ответа
{ "ok": true, "id": 101 } // `boolean` Статус операции, `number` ID нового сообщения
```

**Ответ (HTTP 400 Bad Request):**

```json
// Пример ошибки, если обращение закрыто
{ "error": "Ticket is closed" } // `string` Сообщение об ошибке
```

### DELETE `/api/unified-window/tickets/{token}`

**Описание:** Скрыть обращение пользователем из своей истории. Это действие является "мягким удалением" (soft-delete) для пользовательского интерфейса.

**Параметры пути (Path Parameters):**

| Параметр | Тип | Описание |
| --- | --- | --- |
| `token` | `string` | Уникальный токен доступа к обращению. |

**Ограничение:** Скрывать можно только обращения в статусах `closed` или `resolved`.

**Важно:** Обращение не удаляется из базы данных и остаётся доступным в административной панели до явного удаления администратором.

**Ответ (HTTP 200 OK):** Объект, подтверждающий успешное скрытие.

```json
// Пример успешного ответа
{ "ok": true } // `boolean` Статус операции
```

### GET `/api/getdates`

**Описание:** Получить массив дат (понедельник-воскресенье) для указанной недели. Если для конкретного курса/группы данные отсутствуют, используется расчётный fallback.

**Query-параметры:**

| Параметр | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `week` | `number` | ✓ | Номер учебной недели. |
| `course` | `number` | Нет | Номер курса для уточнения диапазона дат. |
| `group` | `string` | Нет | Название группы для уточнения диапазона дат. |

**Логика:** Для `course` и `group` эндпоинт сначала пытается определить границы недели (`date_start`/`date_end`) из реальных записей в таблице `pairs` для указанной недели. Если данные расписания для этой комбинации отсутствуют, используются общие расчётные даты для недели.

**Ответ (HTTP 200 OK):** Массив строк в формате `YYYY-MM-DD`, представляющий даты с понедельника по воскресенье для указанной недели.

```json
["2025-04-07", "2025-04-08", "2025-04-09", "2025-04-10", "2025-04-11", "2025-04-12", "2025-04-13"]
```

## Административный API (`/adminapi/*`)

Все эндпоинты кроме `/login` и `/checktoken` требуют JWT-токен.

**Авторизация:** заголовок `Authorization: Bearer <token>` или `Token: <token>`

---

### POST `/adminapi/login`

**Описание:** Аутентификация администратора. При успешной аутентификации возвращает JWT-токен для последующих запросов к защищённым административным эндпоинтам.

**Тело запроса (Request Body):** `application/json`

| Поле | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `username` | `string` | ✓ | Логин пользователя административной панели. |
| `password` | `string` | ✓ | Пароль пользователя. |

```json
// Пример запроса
{
  "username": "admin",
  "password": "password123"
}
```

**Ответ (HTTP 200 OK):** Объект, содержащий JWT-токен.

```json
// Пример успешного ответа
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." } // `string` JWT-токен
```

**Срок действия токена:** Токен действителен **24 часа**.

**Ответы с ошибками:**

*   **HTTP 400 Bad Request:**
    ```json
    { "code": "ADM-AUTH-001", "error": "username and password are required" }
    ```
    *   **Описание:** Не передан логин или пароль в теле запроса.

*   **HTTP 401 Unauthorized:**
    ```json
    { "code": "ADM-AUTH-002", "error": "Invalid credentials" }
    ```
    *   **Описание:** Неверные учётные данные (логин или пароль).

*   **HTTP 403 Forbidden:**
    ```json
    { "code": "ADM-AUTH-003", "error": "User is disabled" }
    ```
    *   **Описание:** Учётная запись пользователя отключена.

*   **HTTP 503 Service Unavailable:**
    ```json
    { "error": "Admin users are not configured. Run: npm run seed or npm run users:create -- <username> <password> true" }
    ```
    *   **Описание:** В системе не настроены административные пользователи. Требуется инициализация через скрипты.

**Коды ошибок авторизации (общие для административного API):**

| Код | HTTP Статус | Где возникает | Значение |
| --- | --- | --- | --- |
| `ADM-AUTH-001` | 400 | `POST /adminapi/login` | Не передан логин или пароль. |
| `ADM-AUTH-002` | 401 | `POST /adminapi/login` | Неверные учётные данные. |
| `ADM-AUTH-003` | 403 | `POST /adminapi/login`, `POST /adminapi/checktoken`, любые защищенные маршруты | Учётная запись отключена. |
| `ADM-AUTH-004` | 403 | Любой маршрут с проверкой прав | Недостаточно прав для выполнения действия. |
| `ADM-AUTH-005` | 401 | Любой защищенный маршрут | JWT-токен не передан. |
| `ADM-AUTH-006` | 403 | Любой защищенный маршрут | Токен имеет некорректные claims (например, отсутствует `uid` или `username`). |
| `ADM-AUTH-007` | 401 | Любой защищенный маршрут | Пользователь, указанный в токене, не найден в базе данных. |
| `ADM-AUTH-008` | 401 | Любой защищенный маршрут | Токен недействителен или истёк. |

### GET `/adminapi/unified-window/tickets`

Получить обращения «Единого окна».

**Query-параметры:** `status`, `role`, `limit` (по умолчанию `100`, максимум `500`)

Каждый элемент списка включает:

- `id`, `subject`, `status`, `priority`, `requester_role`, `contact_name`, `contact_email`
- `last_message_author_role` (`user` или `agent`)
- `last_message_at`
- `has_unread_for_agent` (есть непрочитанный ответ пользователя для агента)

### GET `/adminapi/unified-window/tickets/{id}`

Получить детали одного обращения, включая переписку, историю статусов и список вложений.

При открытии обращения автоматически обновляется маркер чтения агента (`agent_last_read_at`).

### PATCH `/adminapi/unified-window/tickets/{id}/status`

Обновление статуса и комментариев обращения.

Если агент меняет статус из `resolved`/`closed` в `open`/`in_progress`, обращение автоматически снова становится видимым пользователю (сбрасывается флаг скрытия `user_hidden_at`).

```json
// Request
{
  "status": "in_progress",
  "comment": "Взято в работу"
}

// Response
{ "ok": true }
```

`status`: `open` | `in_progress` | `resolved` | `closed`

## Формат JSON расписания (импорт)

**Описание:** Ожидаемая структура JSON-файла для загрузки расписания через эндпоинты `/adminapi/createtable` и `/adminapi/updatetable`.

Поддерживаются как `PascalCase`, так и `snake_case` ключи для всех полей.

```json
{
  "Timetable": [ // `array<object>` Массив объектов расписания по неделям
    {
      "WeekNumber": 15,          // `number` Номер учебной недели
      "DateStart": "2025-04-07",   // `string` Дата начала недели (YYYY-MM-DD)
      "DateEnd": "2025-04-13",     // `string` Дата конца недели (YYYY-MM-DD)
      "Groups": [                // `array<object>` Массив объектов групп
        {
          "Course": 2,             // `number` Номер курса
          "GroupName": "ИТ-21",    // `string` Название группы
          "Faculty": "ИТИ",        // `string` Название факультета (может быть пустым, не используется в БД)
          "Days": [              // `array<object>` Массив объектов дней недели
            {
              "Weekday": 1,          // `number` День недели (1=Понедельник)
              "WeekNumber": 15,      // `number` Номер учебной недели
              "Lessons": [           // `array<object>` Массив объектов занятий
                {
                  "Time": 1,             // `number` Номер пары
                  "Type": "Лекция",      // `string` Тип занятия
                  "Subject": "Математика", // `string` Название дисциплины
                  "Teachers": [{ "TeacherName": "Иванов И.И." }], // `array<object>` Массив объектов преподавателей
                  "Auditories": [{ "AuditoryName": "101" }], // `array<object>` М��ссив объектов аудиторий
                  "Date": "2025-04-07",    // `string` Дата занятия (YYYY-MM-DD)
                  "Subgroup": 0,         // `number` Номер подгруппы (0, если нет)
                  "Week": 15             // `number` Номер учебной недели
                }
                // ... другие занятия
              ]
            }
            // ... другие дни
          ]
        }
        // ... другие группы
      ]
    }
    // ... другие недели
  ]
}
```

## Коды ошибок (HTTP Status Codes)

В таблице ниже приведены общие коды ошибок HTTP, которые могут быть возвращены бэкендом, и их значения. Для административного API также существуют специфические коды ошибок авторизации, описанные в разделе `POST /adminapi/login`.

| Код | Значение |
| --- | --- |
| `400 Bad Request` | Неверные входные данные в запросе (наприм��р, отсутствуют обязательные параметры, некорректный формат). Дополнительные детали часто содержатся в поле `error` ответа. |
| `401 Unauthorized` | Токен авторизации не предоставлен, недействителен или истёк. Требуется повторная аутентификация. |
| `403 Forbidden` | Токен авторизации валиден, но у пользователя недостаточно прав для выполнения запрошенного действия. |
| `404 Not Found` | Запрошенный ресурс не найден на сервере. |
| `500 Internal Server Error` | Внутренняя ошибка сервера. Подробности обычно записываются в логи сервера (`logs/server.log`). |
| `503 Service Unavailable` | Сервис временно недоступен, например, из-за проблем с конфигурацией или инициализацией административных пользователей (см. `POST /adminapi/login`). |
