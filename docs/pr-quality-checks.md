# Проверки Pull Request

## Workflow

- `.github/workflows/pr-quality.yml` (`PR Quality Checks`) запускается при открытии, обновлении, переоткрытии PR и ready_for_review для любых целевых веток. Старый Expo Doctor остаётся отдельным workflow без изменений.
- Node.js 22, `npm ci`, внутренние тесты, ESLint, Babel-проверка 64 исходных JS-файлов (количество меняется с кодом), whitespace diff и Expo export iOS/Android.
- После ошибки тестов следующие независимые проверки продолжаются. Ошибки не маскируются `continue-on-error`: job остаётся failure. В GitHub Step Summary выводится таблица результатов. Новый запуск отменяет предыдущий запуск того же PR; лимит 20 минут.
- `npm run lint` использует базовые правила корректности: неопределённые имена, недостижимый код, дубликаты JSX props, неопределённые JSX-компоненты и др. Это не полный stylistic/recommended React Hooks audit. Включение линтера обнаружило legacy-вызов отсутствующего renderGroupCard; он заменён существующим CommunityRow.

## Комментарии, включая форки

`.github/workflows/pr-quality-comment.yml` запускается через `workflow_run` после завершения проверок и обновляет один bot-комментарий с маркером `mykhsu-pr-quality`. В таблицу попадают результаты отдельных шагов и ссылка на полные логи.

Разделение нужно для безопасности fork PR: проверки получают только contents:read, checkout не сохраняет credentials; publisher имеет pull-requests:write, но **не делает checkout, не устанавливает зависимости, не запускает PR-код и не загружает артефакты**. Результаты берутся из GitHub Actions API. Устаревшие результаты для уже изменившегося PR SHA не публикуются. Тексты логов/PR не интерполируются в shell.

**Важно:** workflow `PR Quality Comment` должен сначала оказаться в default branch, иначе GitHub не запустит его через workflow_run. Обычно потребуется сначала слить добавление workflows; комментарии начнут работать на следующих PR/запусках. Для Dependabot/fork запусков применяются обычные ограничения/одобрение GitHub Actions. Секреты и PAT не нужны; организационная политика должна разрешать GITHUB_TOKEN запись комментариев.

## Локальные команды

```sh
npm ci
npm test
npm run lint
npm run check:syntax
npm run check:bundle
```

`check:bundle` создаёт `dist/ci`, который исключён из Git. Это JS/assets export, не компиляция native binary и не проверка внешнего вида на устройстве.

Проверка зависимостей на уязвимости не является блокирующим шагом: в существующем дереве есть предупреждения npm audit, массовое автоматическое обновление зависимостей в этой задаче не выполнялось. Expo Doctor выполняется старым workflow отдельно.

Первый реальный запуск нужно проверить на GitHub: успешный PR, намеренно упавший тест, обновление существующего комментария, PR из форка. В branch protection можно сделать `Tests, lint and bundle` обязательной проверкой.
