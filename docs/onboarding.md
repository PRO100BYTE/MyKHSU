# Первое знакомство

`OnboardingScreen` — нативный экран из четырёх коротких страниц с горизонтальным свайпом, плавным переходом между страницами и компактными карточками возможностей на финальной странице. Ширина pager измеряется по фактическому внутреннему контейнеру, а каждая страница имеет собственную вертикальную прокрутку для маленьких экранов и крупного шрифта; карточки адаптируются к двум или трём колонкам. Нажатие на карточку открывает подробности в доступном нативном `Modal`; его можно закрыть крестиком или системной кнопкой «Назад». Родительский экран управляет отображением через `visible` и скрывает его в `onComplete`.

## Интеграция

```jsx
import AsyncStorage from '@react-native-async-storage/async-storage';
import OnboardingScreen from './components/OnboardingScreen';
import { isOnboardingCompleted } from './utils/onboarding';

// После загрузки шрифтов/основного состояния:
const completed = await isOnboardingCompleted(AsyncStorage);
setShowOnboarding(!completed);

<OnboardingScreen
  visible={showOnboarding}
  onComplete={() => setShowOnboarding(false)}
  theme={theme}
  accentColor={accentColor}
/>
```

`App.js` читает отметку завершения при инициализации, затем после splash/загрузки шрифтов показывает знакомство вместо основного экрана. Существующие установки без отметки увидят его один раз после обновления. `onComplete` вызывается только после явного «Начать» или «Пропустить» и успешной записи `onboarding_completed_v1` в AsyncStorage. При ошибке записи экран остаётся видимым и предлагает повторить действие. Анимации учитывают системную настройку уменьшения движения; все асинхронные действия защищены от вызова после размонтирования и двойного запуска. Запись одноразового флага не менялась и выполняется только при завершении или пропуске.

## Разрешения

При монтировании экран один раз читает текущий статус уведомлений и календаря. Системные запросы не выполняются автоматически и не повторяются на каждом рендере.

- При нажатии кнопки уведомлений вызывается существующий `notificationService.requestPermissions()`. После выдачи разрешения сохраняются `enabled: true`, `news: true` и `schedule: true`, а остальные пользовательские категории сохраняются без изменений.
- В `app.json` настроен `expo-calendar` plugin с русским описанием доступа к календарю; старый дублирующий plugin удалён. Нативные настройки применяются после пересборки.
- Кнопка календаря вызывает новый `Calendar.requestCalendarPermissions()` из `expo-calendar` (Expo SDK 57); статус читается через `getCalendarPermissions()`, экспорт использует объектный API.
- Статусы уведомлений и календаря отображаются раздельно. После возврата из системных настроек статусы обновляются, но новые запросы автоматически не выполняются.
- При отказе показывается объяснение и кнопка открытия системных настроек.
- Экспорт `.ics` использует существующий системный share sheet. Приложение не сохраняет расписание в фотогалерею и не использует `expo-media-library`, поэтому разрешение к фото не запрашивается и новые зависимости не нужны.

## Системные кнопки iOS

`OnboardingNavigation.ios.js` использует настоящие SwiftUI `Button` через `@expo/ui`: `glass` для «Назад», `glassProminent` для «Далее»/«Начать», `buttonBorderShape('capsule')` и системный крупный размер. На iOS 26+ материал, нажатия и форма отрисовываются системой, не `GlassView` вокруг React-кнопки. На старых iOS остаются нативные `bordered`/`borderedProminent`. Текст кнопок использует системную типографику; содержимое знакомства — Montserrat.

Нужна новая нативная сборка с `@expo/ui`. Если модуль ещё не включён в установленный бинарник, временно показываются обычные React-кнопки без имитации стекла. Android/web используют отдельный fallback и не загружают SwiftUI.

## Метаданные

Текст использует актуальные `APP_DEVELOPERS` и `APP_SUPPORTERS` из `utils/constants.js`, те же значения, что и `AboutModal`. Возможности соответствуют текущему About: расписание, новости с офлайн-доступом, карта корпусов, «Студгородок», уведомления, темы и экспорт.
