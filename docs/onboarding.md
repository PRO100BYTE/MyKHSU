# Первое знакомство

`OnboardingScreen` — нативный экран из пяти коротких страниц с горизонтальным свайпом, плавным переходом между страницами и компактными карточками возможностей. Страница разрешений объединяет уведомления, календарь и галерею; финальная страница запускает конфетти только один раз. Ширина pager измеряется по фактическому внутреннему контейнеру, а каждая страница имеет собственную вертикальную прокрутку для маленьких экранов и крупного шрифта; карточки адаптируются к двум или трём колонкам. На��атие на карточку открывает подробности в доступном нижнем прозрачном модальном окне не выше 40% высоты окна; его можно закрыть крестиком, нажатием вне окна или системной кнопкой «Назад». На экране есть краткое описание обработки данных и одна небольшая внешняя ссылка на официальную политику конфиденциальности. Родительский экран управляет отображением через `visible` и скрывает его в `onComplete`.

## Интеграция

```jsx
import AsyncStorage from '@react-native-async-storage/async-storage';
import OnboardingScreen from './components/OnboardingScreen';
import { isOnboardingCompleted } from './utils/onboarding';

// После загрузки шрифтов/основного состояния:
const completed = await isOnboardingCompleted(AsyncStorage);
setShowOnboarding(!completed);

<OnboardingScreen
  visible={showOnboarding}
  onComplete={() => setShowOnboarding(false)}
  theme={theme}
  accentColor={accentColor}
/>
```

`App.js` читает отметку завершения при инициализации, затем после `splash`/загрузки шрифтов показывает онбординг вместо основного экрана. Существующие установки без отметки увидят его один раз после обновления. `onComplete` вызывается только после явного «Начать» или «Пропустить» и успешной записи `onboarding_completed_v1` в `AsyncStorage`. При ошибке записи экран остаётся видимым и предлагает повторить действие. Анимации учитывают системную настройку уменьшения движения; все асинхронные действия защищены от вызова после размонтирования и двойного запуска. Запись одноразового флага не менялась и выполняется только при завершении или пропуске.

## Разрешения

При монтировании экран один раз читает текущий статус уведомлений и календаря. Системные запросы не выполняются автоматически и не повторяются на каждом рендере.

*   При нажатии кнопки уведомлений вызывается существующий `notificationService.requestPermissions()`. После выдачи разрешения сохраняются `enabled: true`, `news: true` и `schedule: true`, а остальные пользовательские категории сохраняются без изменений.
*   В `app.json` настроен `expo-calendar` plugin с русским описанием доступа к календарю; старый дублирующий plugin удалён. Нативные настройки применяются после пересборки.
*   Кнопка календаря вызывает новый `Calendar.requestCalendarPermissions()` из `expo-calendar` (Expo SDK 57); статус читается через `getCalendarPermissions()`, экспорт использует объектный API с `writeOnly: false` для полного доступа к календарю.
*   Статусы уведомлений и календаря отображаются раздельно. После возврата из системных настроек статусы обновляются, но новые запросы автоматически н�� выполняются.
*   При отказе показывается объяснение и кнопка открытия системных настроек.
*   Галерея использует доступ только для добавления `expo-media-library` и `Asset.create()`, без чтения фотобиблиотеки пользователя. Разрешение запрашивается только по явному нажатию кнопки.

## Пять страниц и ограниченные окна

Онбординг состоит из пяти страниц: первая плавно появляется и содержит версию/сборку и ссылку на официальную политику `https://myiti.pro100byte.ru/privacy-policy`; третья содержит уведомления, календарь и галерею; четвёртая — карточки возможностей; пятая сообщает о готовности приложения. На пятой (финальной) странице один раз запускается обильное конфетти: непрерывная анимация с рандомизированными начальными точками в верхней части экрана, полностью падающая за пределы экрана и имеющая регулируемую скорость. Конфетти адаптируется к сезону/празднику и располагается между фоном и элементами логотипа/текста. При открытии первой страницы конфетти не запускаются. Подробности функций и локальное описание разрешений открываются нижними листами (`NativeSheet`) максимум 40% высоты с прокруткой, а не полноэкранными окнами. Модальные окна функций/конфиденциальности онбординга реализованы как ограниченные нижние листы, поддерживающие жесты вертикального расширения/сворачивания и закрытие по фону.

## Системные кнопки iOS

`OnboardingNavigation.ios.js` использует настоящие `SwiftUI Button` через `@expo/ui`: `glass` для «Назад», `glassProminent` для «Далее»/«Начать», `buttonBorderShape('capsule')` и системный крупный размер. На iOS 26+ материал, нажатия и форма от��исовываются системой, не `GlassView` вокруг React-кнопки. На старых iOS остаются нативные `bordered`/`borderedProminent`. Текст кнопок использует системную типографику; содержимое онбординга — Montserrat.

Нужна новая нативная сборка с `@expo/ui`. Если модуль ещё не включён в установленный бинарник, временно показываются обычные React-кнопки без имитации стекла. Android/web используют отдельный fallback и не загружают SwiftUI.

## Метаданные

Текст использует актуальные `APP_DEVELOPERS` и `APP_SUPPORTERS` из `utils/constants.js`, те же значения, что и `AboutModal`. Возможности соответствуют текущему About: расписание, новости с офлайн-доступом, карта корпусов, «Студгородок», уведомления, темы и экспорт.
