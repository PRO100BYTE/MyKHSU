# Первое знакомство

`OnboardingScreen` — нативный экран из четырёх коротких страниц. Родительский экран управляет его отображением через `visible` и скрывает его в `onComplete`.

## Интеграция

```jsx
import AsyncStorage from '@react-native-async-storage/async-storage';
import OnboardingScreen from './components/OnboardingScreen';
import { isOnboardingCompleted } from './utils/onboarding';

// После загрузки шрифтов/основного состояния:
const completed = await isOnboardingCompleted(AsyncStorage);
setShowOnboarding(!completed);

<OnboardingScreen
  visible={showOnboarding}
  onComplete={() => setShowOnboarding(false)}
  theme={theme}
  accentColor={accentColor}
/>
```

`App.js` читает отметку завершения при инициализации, затем после splash/загрузки шрифтов показывает знакомство вместо основного экрана. Существующие установки без отметки увидят его один раз после обновления. `onComplete` вызывается только после явного «Начать» или «Пропустить» и успешной записи `onboarding_completed_v1` в AsyncStorage. При ошибке записи экран остаётся видимым и предлагает повторить действие.

## Разрешения

При монтировании экран один раз читает текущий статус уведомлений и календаря. Системные запросы не выполняются автоматически и не повторяются на каждом рендере.

- При нажатии кнопки уведомлений вызывается существующий `notificationService.requestPermissions()`. После выдачи разрешения сохраняются `enabled: true`, `news: true` и `schedule: true`, а остальные пользовательские категории сохраняются без изменений.
- В `app.json` настроен `expo-calendar` plugin с русским описанием доступа к календарю; старый дублирующий plugin удалён. Нативные настройки применяются после пересборки.
- Кнопка календаря вызывает `Calendar.requestCalendarPermissionsAsync()` (Expo SDK 57), используемый также экспортом в `utils/calendarExport.js`.
- Статусы уведомлений и календаря отображаются раздельно. После возврата из системных настроек статусы обновляются, но новые запросы автоматически не выполняются.
- При отказе показывается объяснение и кнопка открытия системных настроек.
- Экспорт `.ics` использует существующий системный share sheet. Приложение не сохраняет расписание в фотогалерею и не использует `expo-media-library`, поэтому разрешение к фото не запрашивается и новые зависимости не нужны.

## Метаданные

Текст использует актуальные `APP_DEVELOPERS` и `APP_SUPPORTERS` из `utils/constants.js`, те же значения, что и `AboutModal`. Возможности соответствуют текущему About: расписание, новости с офлайн-доступом, карта корпусов, «Студгородок», уведомления, темы и экспорт.
