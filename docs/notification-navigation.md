# Открытие уведомлений

`App.js` обрабатывает нажатие на внешнее уведомление при работающем приложении и последнее нажатие при холодном запуске. Повторная обработка одного ответа в текущем запуске подавляется, обработанный последний ответ очищается через Expo API.

`notificationService.getNotificationRoute()` проверяет тип payload. Новости открывают раздел новостей, события расписания — расписание. Произвольные URL из payload не открываются. На текущем этапе параметры `newsId`, `date` и `scheduleKey` не применяются как детальная навигация: открывается раздел с пользовательскими сохранёнными настройками, а не конкретная новость/пара.

На первом запуске перед основным экраном показывается знакомство с возможностью настройки разрешений (см. `onboarding.md`). Обработка внешнего нажатия сохраняет выбранный раздел, который будет показан после завершения знакомства; конкретные дата/пара пока не применяются.

`InAppNotificationBanner` подключён поверх содержимого и передаёт нажатие тому же обработчику разделов. Единый foreground handler устанавливает сервис уведомлений; отдельного конкурирующего handler в App нет.

Ручная проверка: одно событие в foreground не дублируется системным баннером и внутренним; нажатие из фона и холодного запуска открывает правильный раздел; повторный обычный запуск не возвращает к старому уведомлению. Внешняя доставка требует системного разрешения; фоновые проверки не заменяют backend push.
