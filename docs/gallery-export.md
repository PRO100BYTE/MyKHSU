# Сохранение расписания в галерею

В шапке расписания: «Поделиться» → изображение → «Сохранить в галерею». Создаётся PNG из существующего скрытого `ScheduleShareImage`: полный выбранный день/неделя, а не снимок окна приложения. Системный календарь, файл .ics и отправка изображения через share sheet остаются отдельными действиями.

`utils/galleryExport.js` использует новый объектный `Asset.create(uri)` SDK 58. Исходный путь снимка не изменяется; временный снимок освобождается после завершения сохранения/отправки. Сохранение не читает и не перечисляет фотографии пользователя.

Разрешение запрашивается только явной кнопкой знакомства или при выборе сохранения. iOS получает add-only (`writeOnly: true`), Android — без granular read-разрешений (`[]`); на новых Android системный диалог для добавления собственного изображения может не требоваться. При отказе доступна ссылка в настройки, при отсутствии нативного модуля — сообщение о недоступности функции.

Plugin `expo-media-library` задаёт русское описание `NSPhotoLibraryAddUsageDescription`, выключает запрос чтения Photos и геометаданные медиа. **Нужна пересборка приложения**: OTA/Metro не добавляют нативный модуль или Info.plist. Итоговая конфигурация проверена через `expo config --type introspect`: iOS имеет только описание добавления фото, Android manifest не содержит `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO` или `READ_MEDIA_AUDIO`.

На устройстве проверить: выдачу/отказ add-only, отсутствие чтения библиотеки, повторное сохранение, PNG полного расписания, возврат из настроек, очистку временного снимка и сохранность прежнего share/calendar экспорта.
