# Прокрутка под плавающим заголовком

`components/ScreenScrollView.js` — совместимая с React Native `ScrollView` обёртка для корневого содержимого экранов. Импорт: `import ScrollView from './ScreenScrollView'`.

На iOS вертикальная корневая прокрутка получает **прокручиваемый** `contentContainerStyle.paddingTop`: высота перекрытия заголовком + существующий верхний padding (не менее 16 pt). Первый элемент находится ниже glass-заголовка, а при прокрутке проходит под ним. Viewport остаётся полноэкранным. Отрицательный начальный `contentOffset` и дополнительный нативный `contentInset` больше не используются: начальная видимость не зависит от порядка нативной раскладки и восстановления scroll position.

`useScreenHeaderInset()` возвращает общую оценку нижнего края iOS-заголовка: safe area + marginTop 6 + paddingVertical 12 × 2 + высота текста 18 (с запасом на метрики шрифта и Dynamic Type) + границы. Это **не измерение**: при изменении геометрии заголовка в `App.js` нужно синхронизировать формулу; для нестандартного/многострочного заголовка следует передать измеренный `headerInset`. Обёртка должна находиться внутри `SafeAreaProvider`, контейнер — занимать всю доступную высоту без дополнительного верхнего safe-area padding.

## API

- Все обычные props `ScrollView` и `ref` передаются нативному компоненту.
- `underlap` (по умолчанию `true`): `false` отключает добавление padding, например для самостоятельных модальных окон.
- `headerInset`: полная высота верхнего перекрытия (без 16 pt зазора); по умолчанию `useScreenHeaderInset()`.
- `contentContainerStyle` поддерживает массивы стилей и `paddingTop` / `paddingVertical` / `padding`. Остальные отступы сохраняются, верхний зазор не удваивается.
- Переданные `contentInset` и `contentOffset` сохраняются без изменений. Не нужно добавлять в них высоту заголовка повторно. Явное ненулевое смещение по-прежнему может скрыть начало содержимого.
- `scrollIndicatorInsets.top` добавляется к высоте перекрытия. Автоматическая коррекция content/indicator inset отключена, чтобы iOS не добавляла safe area второй раз.
- На Android/web, для `horizontal` и для вложенных обёрток padding не добавляется. Контекст вложенности предотвращает двойной отступ.

Переведены настройки и их подразделы, расписание, новости, корневые прокрутки раздела первокурсника, сообщество и список корпусов. У списка корпусов поиск и счётчик включены в общую прокрутку. Старые ветки VK и статической Telegram-заглушки также используют общий scroll container; верхний padding не должен находиться на внешнем `View`.

В расписании padding перенесён из viewport в содержимое. Порог появления фиксированного заголовка учитывает новый начальный spacer (`offsetY - headerInset > 100`), сам заголовок расположен ниже glass-панели (`headerInset + 8`), переход к текущей дате вычитает перекрытие и прежние 150 pt для локального заголовка. Избранное в самостоятельном Modal явно использует `underlap={false}`.

`MapScreen` использует полноэкранный `MapView` без верхнего padding. Прокрутка фильтров находится в нижней панели и остаётся нативной. Другие самостоятельные модальные окна (включая свободные аудитории) также не получают padding. Активных корневых `FlatList` / `SectionList` сейчас нет (`FlatList` в ScheduleFormatModal только импортирован); при их добавлении нужен аналогичный padding содержимого, не внешний отступ viewport.

## Проверка

Автоматическая: `node --test tests/*.test.cjs` — проверка spacer, shorthand/массивов стилей, явных inset/offset, Dynamic Type, вложенности, opt-out и платформ.

Ручная на iOS (симулятор/устройство):

1. После холодного запуска и переключения вкладок открыть новости: поиск виден ниже glass-панели с зазором около 16 pt. Карточки проходят под панелью; pull-to-refresh работает.
2. Проверить настройки и подразделы, первокурснику, звонки, глоссарий, сообщества и корпуса: первый элемент читаем, низ списка доступен, поиск корпусов прокручивается вместе со списком.
3. В расписании проверить дневной и недельный режимы, преподавателя/аудиторию, появление локального заголовка, автоматический переход к сегодняшнему дню и возврат `ref.scrollTo({ y: 0 })`. Проверить избранное: нет дополнительного отступа в модальном окне.
4. Проверить safe area на iPhone с вырезом и без него, поворот экрана, увеличенный системный шрифт, загрузку/пустые данные/ошибки сети.
5. Открыть карту и фильтры: карта полноэкранная, в панели фильтров нет лишнего верхнего отступа.
6. Проверить Android/web: дополнительный spacer не применяется.
